# EOM General Migration Model — Architecture Amendment (13 October 2026)

## Scope correction
The core research objective is a **general migration model**, based on the EOM paper's energy structure. The Tech MBA pathway is merely an optional example of user-supplied scenario parameters. It is not the model's defining target, and programme-level MBA outcomes must not determine or dominate the core model architecture.

## Intended research targets
1. General destination attractiveness and migration flows/stocks.
2. Origin–destination transitions where bilateral data are available.
3. Changes across time and heterogeneity across migrant groups where data definitions and sample sizes support it.
4. Policy/economic counterfactuals, but only where a defensible causal design is available.
5. User-defined scenarios expressed through parameters such as origin, destination, profile, objectives, constraints and horizon.

## Feedback loop added to the package
The `data/model_feedback/` directory now contains blank, auditable schemas for:
- `prediction_ledger_template.csv`: forecasts recorded before outcomes are observed;
- `outcome_ledger_template.csv`: observations matched to prior forecasts;
- `evaluation_run_template.csv`: chronological out-of-sample metrics and baseline comparisons;
- `causal_evaluation_register_template.csv`: policy shock, design, assumptions, diagnostics and effect estimates;
- `model_version_registry.csv`: the current conceptual/unfitted status and version history;
- `origin_destination_year_panel_template.csv`: a proposed bilateral panel schema;
- `baseline_coverage_and_status_2026-10-13.json`: actual current data and evaluation coverage metrics.

These are pipeline structures, not populated model results. No fitted weights, predictions, chronological backtest or causal effect was generated by this architecture change.

## Existing data snapshot
- `historical_destination_year_panel.csv`: 756 rows, 21 destinations, years 1990–2025. This is a country/destination-year scaffold, not evidence of 36 complete annual observations for every variable; indicator coverage is intermittent.
- `eurostat_new_migration_indicators_long.csv`: 396 observations across 33 destinations, 2019–2024, with indicator classification/status/unit fields.
- Existing data quality audit: 63 destination-indicator audit rows.
- Prediction and outcome ledgers: empty because no forecast/outcome matching has yet been recorded in this package.
- Causal evaluation register: empty.

## Required scientific safeguards
- First map the paper's exact energy equation to measurable indicators and define target variables.
- Retain equal-weight baseline calculations separately from any estimated parameters.
- Use rolling/expanding chronological train-test evaluation, not random splits for time-indexed data.
- Compare against simple baselines and report observation counts, temporal/geographic coverage, missingness, uncertainty and metrics.
- Keep prediction and causal inference separate. Feedback loops alone do not establish causality.
- Preserve forecasts, source vintages and prior model versions; a policy headline must not automatically retrain the model.
- Revise models only after diagnosing errors and demonstrating credible later-period performance.
- Do not label EOM calibrated or validated until the relevant evaluation supports that statement.

## Next empirical bottleneck
The next step is to audit the user's EOM equations and existing derived-energy calculations, define outcomes that can be observed consistently over time, create a sourced prediction ledger, and determine which indicators support a comparable origin–destination panel. Then implement baseline and chronological evaluation before estimating complex parameters.
